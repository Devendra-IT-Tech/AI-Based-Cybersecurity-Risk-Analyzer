## Abstract

This project presents an **AI-Based Cybersecurity Threat Risk Analyzer**, a web application that combines modern Large Language Model (LLM) technology with classical Fuzzy Logic to analyze cybersecurity incidents described in natural language.

The system uses **LangChain** with **Google Gemini 3.8 Flash** to extract structured threat intelligence from unstructured text. These extracted factors—threat likelihood, potential impact, exposure, and data sensitivity—are then fed into a genuine **Fuzzy Inference System** (FIS) built with scikit-fuzzy. The FIS applies membership functions, evaluates 17 fuzzy rules using the Mamdani inference method, aggregates the outputs, and applies centroid defuzzification to produce a numerical risk score in the range [0, 100]. The score is categorized as LOW, MEDIUM, HIGH, or CRITICAL. The LLM then generates a plain-English explanation and defensive recommendations.

The application is deployed as a **Streamlit** web application, making it accessible to non-technical users. It is ready for deployment on **Streamlit Community Cloud** and is available on **GitHub**.

## 1. Introduction

Cybersecurity incidents are becoming increasingly frequent and sophisticated. Organizations of all sizes must rapidly assess the severity of security events to prioritize responses. Traditional rule-based systems lack the ability to handle the nuance and ambiguity inherent in cybersecurity risk assessment.

This project addresses this challenge by combining two complementary AI approaches:

1. **Large Language Models (LLM)** — to understand and structure natural-language incident descriptions.
2. **Fuzzy Logic** — to evaluate the inherent uncertainty in risk assessment and produce a calibrated risk score.

The combination reflects a real-world principle: language models excel at understanding context, while fuzzy logic excels at reasoning under uncertainty with human-interpretable rules.

## 2. Problem Statement

Security analysts often receive vague, informal incident reports written in natural language. Manually assessing the risk of each incident is:

- **Time-consuming** — requires expert judgment.
- **Inconsistent** — different analysts may rate the same incident differently.
- **Difficult to justify** — crisp threshold-based scoring lacks explainability.

**Goal:** Build an automated system that takes a natural-language incident description and produces a justified, explainable cybersecurity risk score using AI and fuzzy logic.

## 6. AI / LangChain Component

### 6.1 Overview

LangChain is used as the orchestration framework for all LLM interactions. Three distinct chains are implemented:

### 6.2 Chain 1 — Factor Extraction

**Purpose:** Extract structured cybersecurity intelligence from natural-language text.

**Flow:**
```
PromptTemplate (System + Human) → ChatGoogleGenerativeAI → StrOutputParser → JSON Parser → Pydantic Validator
```

**Extracted fields:**
| Field | Type | Range |
|-------|------|-------|
| threat_type | string | Categorical |
| attack_vector | string | Categorical |
| affected_asset | string | Categorical |
| suspicious_activity | string | Descriptive |
| sensitive_data_involved | string | Yes/No/Unknown |
| likelihood | float | 0–100 |
| impact | float | 0–100 |
| exposure | float | 0–100 |
| data_sensitivity | float | 0–100 |

All numeric outputs are validated to be within [0, 100] by Pydantic. Invalid values fall back to safe defaults.

### 6.3 Chain 2 — Risk Explanation

**Purpose:** Generate a 3–5 sentence plain-English explanation of the risk assessment.

The LLM receives the extracted factors AND the fuzzy-computed risk score. It explains the score but does NOT compute it. This maintains the architectural separation.

### 6.4 Chain 3 — Defensive Recommendations

**Purpose:** Generate 4–6 safe, practical defensive actions.

Output is parsed as a JSON array and validated. If parsing fails, predefined safe fallback recommendations are used.

### 6.5 Security Measures
- API key never hard-coded.
- All LLM JSON output validated before use.
- LLM never decides the final numerical risk score.
- Malformed output handled gracefully.

## 7. Fuzzy Logic Component

### 7.1 Why Fuzzy Logic?

Real-world cybersecurity risk is inherently imprecise:
- "This threat has a **medium-high** likelihood" cannot be expressed as a crisp number.
- Fuzzy logic allows membership in multiple sets simultaneously (partial truth).
- It models expert knowledge as human-readable IF-THEN rules.
- The result is inherently explainable.

### 7.2 Universe of Discourse

All input and output variables use the universe: **[0, 100]**

### 7.3 Membership Functions

**Input variables** (Likelihood, Impact, Exposure, Data Sensitivity):

| Term | Type | Parameters |
|------|------|-----------|
| Low | Trapezoidal | [0, 0, 35, 50] |
| Medium | Triangular | [30, 50, 70] |
| High | Trapezoidal | [55, 75, 100, 100] |

**Output variable** (Risk):

| Term | Type | Parameters |
|------|------|-----------|
| Low | Trapezoidal | [0, 0, 20, 30] |
| Medium | Triangular | [20, 35, 55] |
| High | Triangular | [45, 65, 80] |
| Critical | Trapezoidal | [70, 85, 100, 100] |

### 7.4 Fuzzification

Each crisp input value is converted to a degree of membership in each fuzzy set using `skfuzzy.interp_membership()`. For example, a likelihood value of 70 might yield:
- Low: 0.0
- Medium: 0.0
- High: 0.83

### 7.5 Rule Base (Mamdani-style)

17 fuzzy rules are implemented. Selected examples:

```
R1:  IF Likelihood=Low AND Impact=Low AND Exposure=Low     THEN Risk=Low
R4:  IF Likelihood=High AND Impact=High AND Exposure=High  THEN Risk=Critical
R5:  IF Impact=High AND Exposure=High                      THEN Risk=High
R9:  IF DataSensitivity=High AND Likelihood=High           THEN Risk=Critical
R13: IF Likelihood=Medium AND Impact=Medium                THEN Risk=Medium
```

### 7.6 Rule Evaluation

Each rule is evaluated using the **minimum (AND) operator**:
```
activation_strength = min(antecedent_memberships)
```

The consequent membership function is clipped at the activation strength.

### 7.7 Aggregation

All clipped consequent membership functions are aggregated using the **maximum (OR) operator**:
```python
aggregated = np.fmax(rule_output_1, np.fmax(rule_output_2, ...))
```

### 7.8 Defuzzification

The **centroid (centre of gravity) method** is applied to the aggregated output:
```python
risk_score = skfuzzy.defuzz(universe, aggregated, 'centroid')
```

This produces a single crisp value in [0, 100].

### 7.9 Risk Level Mapping

| Score Range | Risk Level |
|------------|-----------|
| 0 – 24.99 | LOW |
| 25 – 49.99 | MEDIUM |
| 50 – 74.99 | HIGH |
| 75 – 100 | CRITICAL |

## 10. Methodology

1. **User Input** — Natural-language incident description entered via Streamlit text area.
2. **LLM Extraction** — LangChain sends the text to Gemini 3.8 Flash with a structured extraction prompt. The response is parsed and validated.
3. **Fuzzy Inference** — The validated numeric factors (likelihood, impact, exposure, data_sensitivity) are fuzzified, rules are evaluated, outputs aggregated, and defuzzification produces the risk score.
4. **Result Display** — Risk score, level, LLM explanation, and recommendations are displayed in the Streamlit UI.
5. **Visualisation** — Membership function plots and a live fuzzy tester are available in a dedicated tab.

---

## 11. Implementation

### Key Design Decisions

- **Separation of concerns**: LLM extracts factors; fuzzy engine computes the score. Neither can directly affect the other's core responsibility.
- **Defensive programming**: Every external call (LLM) is wrapped with error handling. Invalid outputs fall back to safe defaults.
- **Pydantic validation**: All LLM output is validated before being passed to the fuzzy engine.
- **No hard-coded keys**: API keys are loaded from environment variables only.
- **Modular structure**: Each responsibility has its own module (llm_service, fuzzy_engine, risk_analyzer, validators, prompts).

### Module Responsibilities

| Module | Responsibility |
|--------|---------------|
| `app.py` | Streamlit UI, page layout, visualisation |
| `src/llm_service.py` | LangChain chains, Gemini calls, JSON parsing |
| `src/fuzzy_engine.py` | Complete FIS: MFs, fuzzification, rules, aggregation, defuzzification |
| `src/risk_analyzer.py` | Pipeline orchestration |
| `src/validators.py` | Pydantic models for all data structures |
| `src/prompts.py` | All LangChain prompt templates |
| `utils/sample_cases.py` | Pre-built demo scenarios |
